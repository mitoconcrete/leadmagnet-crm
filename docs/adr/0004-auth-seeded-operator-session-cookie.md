# ADR 0004. 시드 운영자 계정 + 서버 세션 쿠키 인증

- 상태: 채택 (2026-09-09)

## 맥락
"인증한 운영자만 관리자 기능과 신청자 데이터를 볼 수 있어야 한다." 운영자는 소수이고 가입 흐름은 요구사항에 없다. 인증 토큰이 브라우저 저장소에 있으면 등록 HTML 격리 요구와 충돌할 수 있다.

## 결정
- 회원가입 없음. `.env`의 `ADMIN_EMAIL`/`ADMIN_PASSWORD`로 기동 시 운영자 1명을 upsert(bcrypt cost 10).
- 로그인 성공 시 `sessions` 테이블에 행을 만들고 세션 id를 `sid` 쿠키로 발급한다. `HttpOnly; SameSite=Lax; Path=/api/admin; Max-Age=7일`.
- `/api/admin/*` 전역 `AuthGuard`가 쿠키 → 세션 → 만료를 검사한다.

## 근거
- HttpOnly 쿠키는 스크립트로 읽을 수 없어 XSS·iframe 우회에 강하다. JWT를 localStorage에 두는 방식보다 격리 요구에 맞는다.
- 서버 세션은 로그아웃 즉시 무효화가 가능하고 구현이 단순하다.
- Path 한정으로 공개 경로에 쿠키가 새지 않는다(ADR 0003).

## 대안
- JWT Bearer: 무상태이지만 토큰 보관 위치 문제와 즉시 폐기 불가.
- 회원가입 + 역할: 요구사항 밖, YAGNI.

## 결과
- 세션 테이블 청소(만료 행 삭제)는 로그인 시 기회적으로 수행한다.
- 브루트포스 방어(레이트 리밋)는 범위 밖으로 두고 ADR에 남긴다.
