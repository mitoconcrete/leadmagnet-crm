# ADR 0021. 데스크톱 우선 레이아웃: 바깥 화면은 뷰포트에 고정, 스크롤은 섹션 안에서만

- 상태: 채택 (2026-09-10)

## 맥락
관리자 화면은 지금까지 모바일 우선(세로 한 열, 페이지 스크롤)으로 만들어졌다. 과제에 모바일 조건은 없고, 실제 운영자는 데스크톱에서 여러 표(캠페인·채널·폼·명단)를 한눈에 본다. 표가 길어지면 페이지가 늘어나 상단 요약과 하단 명단을 오가야 하고, 어느 섹션이 갱신됐는지 시야에서 놓친다. 기획에 없던 항목이라 가정을 세워 기록한다.

## 결정
- **데스크톱 우선.** 기준 뷰포트 1280px 이상, 검증 뷰포트 1440×900. 좁은 화면(<1024px)은 열을 세로로 쌓아 "쓸 수는 있는" 수준만 보장한다.
- **바깥 문서는 스크롤하지 않는다.** 앱 셸은 `h-screen` 그리드(상단 내비 고정 높이 + `main` `overflow-hidden`)이고, 페이지는 `grid`와 `min-h-0`로 남은 높이를 섹션에 나눠 준다. 스크롤은 각 섹션(Card) 본문(`overflow-y-auto`) 안에서만 생긴다. 좁은 화면(폭 < 1024px)에서 열을 세로로 쌓을 때만 바깥 스크롤을 허용한다(구현은 폭 기준 `lg:` 분기).
- 섹션 헤더(제목, 마지막 갱신, 버튼)는 스크롤 영역 밖에 고정한다. 표 헤더는 sticky.
- 페이지별 배치:

| 페이지 | 배치(데스크톱) |
|---|---|
| `/` 대시보드 | 상단 바: 제목 · 마지막 갱신 · 지금 갱신 · 캠페인 생성. 본문 2열: 좌 2/3 캠페인 성과 표(스크롤), 우 1/3 채널 성과 표(5행 고정) |
| `/campaigns/[id]` | 상단 바: 이름 · 상태 배지 · 종료/재개 · 마지막 갱신 · 지금 갱신. 본문 3열: 좌 성과 카드 4개 + 채널 breakdown, 중 폼 목록(폼마다 배포 링크 4채널을 항상 펼쳐 표시 — 접기 없음, 2026-09-10 개정: 운영자가 링크를 바로 복사하는 것이 이 화면의 주목적이라 한 번 더 클릭하게 하지 않는다. 폼 생성 버튼은 열 헤더), 우 신청 명단(페이지네이션은 열 하단 고정) |
| `/templates` | 상단 바에 "새 템플릿 등록" 버튼 1개(2026-09-10 개정: 좌 등록 열이 좁아 등록 폼을 넓은 모달로 분리). 본문은 템플릿 목록이 전폭·자체 스크롤. 등록 모달(`max-w-3xl`, 최대 높이 85vh, 내부 스크롤): AI 생성 안내 + 파일/붙여넣기 탭 + 이름 + 등록 버튼. 미리보기·코드·삭제 Dialog는 그대로 |
| `/login` | 변경 없음(중앙 카드) |

- 대화상자(2026-09-10): 코드 보기·미리보기 Dialog는 `max-w-5xl`, 높이 85vh, 본문(`<pre>`/iframe)이 `flex-1 min-h-0`로 내부 스크롤.
- 템플릿 페이지 좌 열(2026-09-10): AI 안내 박스는 상단 고정(`shrink-0`), 등록 폼 섹션만 `min-h-0 overflow-y-auto`. 붙여넣기 textarea는 고정 높이(예: 16행) + 내부 스크롤이라 긴 HTML을 붙여도 페이지가 밀리지 않는다. 등록 버튼은 등록 폼 섹션의 고정 푸터(스크롤 영역 밖)에 두어 항상 보인다. 대화상자 폭은 shadcn 기본 `sm:max-w-sm`을 `sm:max-w-none` + `w-[min(64rem,95vw)]`로 덮어야 적용된다(2026-09-10).
- 표 헤더(2026-09-10): 모든 표의 `TableHeader`는 sticky(채널 표·breakdown 포함).
- 폼 생성 대화상자의 템플릿 선택(2026-09-10): 검색 가능한 콤보박스(Popover + Command). 트리거는 `w-full` 고정 폭에 선택된 **이름**을 줄임표로 표시, 입력으로 필터.
- 텍스트 밀도는 데스크톱 기준으로 올린다: 표 셀 padding 축소(`py-2`), 본문 14px, 숫자 열 우측 정렬·고정폭 숫자(`tabular-nums`).

## 근거
- 운영 화면의 가치는 비교다. 캠페인 표와 채널 표, 폼과 명단이 같은 화면에 있어야 "어느 채널이 어느 폼에서 전환되는지"를 한눈에 본다.
- 바깥 스크롤을 없애면 섹션 헤더와 갱신 시각이 항상 보이고, 30초 자동 갱신(ADR 0016)이 어디를 바꿨는지 인지된다.
- 세로 열 쌓기(모바일)는 CSS 그리드의 `lg:` 분기로 유지되므로 비용이 거의 없다.

## 대안
- 모바일 우선 유지 + 섹션 스크롤만: 페이지가 여전히 길고 데스크톱에서 좌우 공간이 비어 가독성이 낮다.
- 탭으로 섹션 전환: 한 번에 하나만 보여 비교가 안 된다.

## 결과
- 스펙 §5 갱신. 검증: RTL로 셸·페이지 컨테이너의 레이아웃 클래스(`h-screen`, `overflow-hidden`, `min-h-0`, 열 그리드)와 각 섹션의 `overflow-y-auto`를 단언하고, Playwright `e2e/layout.spec.ts`가 1440×900에서 대시보드(캠페인 30개)·캠페인 상세(폼 10개, 신청 60건)·템플릿(20개)의 `document.documentElement.scrollHeight <= window.innerHeight`를 실측한다.
- ADR 0016의 "마지막 갱신" 표시는 각 페이지 상단 바로 옮긴다.
