# ADR 0014. 템플릿 생애주기: 불변, 참조 없을 때만 삭제, 미리보기·코드 보기, 붙여넣기 등록

- 상태: 채택 (2026-09-10), 삭제 규칙 개정 (2026-09-10)

## 맥락
과제 요구는 "AI로 만든 단일 `.html` 파일 등록"과 "등록한 HTML로 캠페인·폼 생성"까지다. 운영해 보면 바로 드러나는 빈틈이 있다. 등록한 HTML을 확인할 수단이 없고(공개 URL을 열면 방문이 기록돼 통계가 오염된다), 잘못 올린 템플릿을 정리할 수 없으며, 외부 AI(챗 화면)는 파일을 내려 주는 게 아니라 HTML 텍스트를 보여 주므로 운영자가 파일로 저장하는 단계가 하나 더 든다. 과제 안내의 "요구사항이 불분명하면 합리적인 가정을 세우고 ADR에 기록"에 따라 아래를 가정하고 결정한다.

## 결정

| 항목 | 결정 | 가정과 근거 |
|---|---|---|
| 수정 | **불가**. `PATCH/PUT /api/admin/templates/:id` 없음 | 템플릿은 이미 배포된 공개 페이지가 참조한다. 내용을 바꾸면 SNS에 올린 링크의 폼이 예고 없이 달라지고, 과거 신청의 payload 키가 현재 폼과 어긋난다. 바꾸려면 새 템플릿을 등록하고 새 폼을 만든다(불변 자산) |
| 삭제 | `DELETE /api/admin/templates/:id` → 204. 참조하는 폼이 없으면 hard delete. 참조하는 폼이 있으면 409 `'사용 중인 템플릿입니다(폼 N개, 방문 X건, 신청 Y건)'` + `details: {forms, visits, submissions}`. 화면은 이 응답으로 **정말 삭제할지 확인 대화상자**를 띄우고, 확인하면 `DELETE /:id?force=true` → **소프트 삭제**(`deleted_at` 설정) + 참조 폼 전부 `is_active=false`를 **한 트랜잭션**으로 수행 → 204. 소프트 삭제된 템플릿은 목록·상세·미리보기에서 404. 없는 id 404 | 이미 배포되고 이벤트(방문·신청)가 발생한 템플릿은 실수로 지우면 안 되므로 확인을 거친다. 확인 후에도 행을 물리 삭제하지 않는 이유는 FK(`forms.template_id`)와 집계 근거를 보존하기 위해서다. 공개 페이지는 폼 비활성으로 닫힌다 |
| 미리보기 | `GET /api/admin/templates/:id/preview` → `text/html`. 공개 페이지와 같은 래퍼(sandbox `allow-scripts allow-forms`, 같은 CSP, `X-Frame-Options: SAMEORIGIN`, `no-store`). 제출 스크립트 미주입, 방문·쿠키 미기록 | 렌더 확인은 격리 3겹(ADR 0003) 안에서만 한다. 관리자 화면은 이 응답을 `sandbox` iframe으로 연다(`allow-same-origin` 없음) |
| 코드 보기 | 기존 `GET /api/admin/templates/:id`의 `html`을 화면에서 **텍스트로만** 표시 + 복사 버튼 | 관리자 화면에서 등록 HTML을 절대 렌더하지 않는다는 원칙 유지. 미리보기가 렌더, 코드 보기가 원문 |
| 붙여넣기 등록 | `POST /api/admin/templates` multipart에 `file` **또는** `html`(텍스트 필드) 중 하나. `html`일 때 `name` 필수, 저장 파일명 `{name}.html`. 검증은 동일(512KB, `<form` 필수). 둘 다 없거나 둘 다 있으면 400 | 외부 AI는 파일이 아니라 텍스트를 준다. 엔드포인트를 늘리지 않고 같은 자원·같은 검증을 쓴다. 화면은 탭(파일 / 붙여넣기) 하나로 처리 |

## 근거
- "등록 → 확인 → 폼 생성 → 배포"에서 확인 단계가 비어 있었다. 미리보기와 코드 보기는 그 단계를 채우되 관리자 화면의 격리 원칙을 지킨다.
- 삭제 제한과 수정 금지는 같은 원칙에서 나온다. 배포된 것은 바꾸지 않는다. 통계와 공개 링크의 안정성이 운영자 편의보다 앞선다.
- 붙여넣기는 입력 경로만 늘리고 저장 이후 흐름은 그대로다. 검증 함수가 파일·텍스트를 같은 인터페이스(`{originalname, size, buffer}`)로 받는다.

## 대안
- 템플릿 수정 허용 + 버전 관리: 정확하지만 폼-템플릿 버전 연결과 화면이 필요해 범위가 커진다. 다음 단계 후보.
- 참조 중이면 삭제 전면 금지: 가장 일관되지만 실수로 올린 템플릿에 폼을 붙인 뒤 정리할 방법이 없다. 확인 대화상자 + 소프트 삭제가 절충이다.
- 복구 UI: `deleted_at`만 지우면 되므로 필요해지면 작다. 지금은 두지 않는다.
- 붙여넣기 전용 JSON 엔드포인트: 자원이 둘로 갈라지고 문서·테스트가 늘어난다.

## 결과
- 스펙 §4.2·§5 갱신, e2e·Bruno·화면 테스트 추가. ADR 0013의 미리보기 행은 이 문서로 옮긴다.
- 면접 질문 예상: "왜 수정이 안 되나" → 배포된 링크와 과거 신청의 일관성. "삭제가 왜 막히나" → 공개 페이지와 집계 근거 보존.
