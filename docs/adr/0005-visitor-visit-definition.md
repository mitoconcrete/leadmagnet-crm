# ADR 0005. 방문·방문자 정의와 채널 귀속

- 상태: 채택 (2026-09-09)

## 맥락
"캠페인별 방문, 방문자, 신청, 전환율"과 "채널별 성과"를 보여 줘야 한다. 방문과 방문자를 구분하려면 사람을 식별하는 기준이 필요하고, 신청을 어느 채널에 귀속할지 규칙이 필요하다.

## 결정
- **방문(visit)** = `GET /p/:slug` 응답 1회. 새로고침도 방문으로 센다.
- **방문자(visitor)** = 공개 오리진에 발급한 쿠키 `vid`(`Path=/p; HttpOnly; SameSite=Lax; 1년`)의 고유 id. 첫 방문 때 `visitors` 행을 만들고 이후 방문은 같은 id를 재사용한다.
- **채널 귀속** = 배포 링크 `?src=CODE`가 유효하면 그 링크의 채널, 아니면 `direct`. 각 방문 행이 채널을 가진다.
- **신청 귀속** = 제출 본문의 `visitToken`(방문 id)이 가리키는 방문의 방문자·링크·채널을 그대로 복사한다. 즉 "마지막 클릭" 귀속이다.

## 근거
- 쿠키 기반 식별은 공유 IP·NAT 환경에서 IP+UA 해시보다 정확하고 구현이 단순하다.
- 방문 행이 채널을 스냅샷으로 가지므로 링크가 삭제돼도 집계가 흔들리지 않는다.
- visitToken을 서버가 주입 스크립트에 넣어 주므로 sandbox iframe(쿠키 접근 불가)에서도 귀속이 가능하다.

## 대안
- IP+User-Agent 해시: 쿠키 없이 동작하지만 정확도가 낮다.
- 최초 클릭 귀속: 방문자 최초 유입 채널을 저장해야 하고 캠페인 간 교차 시 해석이 복잡하다.

## 결과
- 쿠키를 지우거나 다른 브라우저를 쓰면 새 방문자로 센다. 과제 범위에서 수용한다.
- 봇 필터링은 하지 않는다.
- 방문 1회(visit)당 신청은 1건이다(`submissions.visit_id` UNIQUE). 같은 방문 토큰으로 재제출하면 409. 그래서 전환율은 1.0을 넘지 않는다(ADR 0006).
