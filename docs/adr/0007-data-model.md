# ADR 0007. 데이터 모델: 템플릿·캠페인·폼·배포 링크·방문·신청

- 상태: 채택 (2026-09-09)

## 맥락
"등록한 HTML을 바탕으로 캠페인과 커스텀 신청 폼"을 만들고 "채널별 배포 링크"를 만든다. 관계를 어떻게 잡느냐가 집계 쿼리와 화면 구조를 결정한다.

## 결정
- `html_templates` 1:N `forms`, `campaigns` 1:N `forms`, `forms` 1:N `distribution_links`(채널당 1개, `UNIQUE(form_id, channel)`), `forms` 1:N `visits`, `forms` 1:N `submissions`, `visitors` 1:N `visits`.
- "커스텀 폼"은 템플릿을 참조하고 이름·slug·성공 메시지·활성 여부만 가진다. HTML 자체를 복제하지 않는다.
- 신청은 `payload JSONB`로 저장한다(스키마 없음).

## 근거
- 템플릿을 여러 캠페인·폼이 재사용할 수 있어야 "AI로 만든 HTML을 등록"하는 행위와 "폼 생성"이 분리된다.
- 채널당 링크 1개면 채널별 성과 = 링크별 성과라 화면이 단순하다.
- 폼 단위로 visits/submissions를 매달면 캠페인 집계는 조인 한 번이고, 폼별 집계도 공짜로 나온다.

## 대안
- 폼이 HTML 사본을 가짐: 템플릿 수정 영향이 없어지지만 저장 중복. 과제에서는 템플릿을 수정하지 않으므로 불필요.
- 채널당 링크 N개: 게시물별 추적이 가능하지만 화면과 집계가 복잡해진다.

## 결과
- 캠페인·폼 삭제 API는 만들지 않는다(보관 상태로 대체). 삭제 시 집계 보존 문제를 피한다.
- 템플릿 수정은 새 템플릿 등록으로 대체한다.
