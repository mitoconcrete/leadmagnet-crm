# ADR 0019. 캠페인 생애주기: 진행중 → 종료(보관), 종료 시 폼 자동 비활성

- 상태: 채택 (2026-09-10), 삭제·활성 폼 표시 개정 (2026-09-10)

## 맥락
캠페인은 `active | archived` 상태와 `PATCH /api/admin/campaigns/:id {status}` API가 있지만, 화면에 종료 버튼이 없고 종료해도 소속 폼의 공개 페이지가 계속 열려 있었다. "진행중밖에 없는데 종료는 어디서 하나"라는 질문이 이 공백을 드러냈다. 기획에 없던 항목이라 가정을 세워 기록한다.

## 결정
- 캠페인 상태는 두 가지만 둔다. **진행중(active)** 과 **종료됨(archived)**.
- **삭제는 이벤트가 없을 때만**(개정): `DELETE /api/admin/campaigns/:id`는 소속 폼의 방문·신청이 모두 0건일 때만 허용하고 폼·배포 링크를 함께 hard delete한다(트랜잭션). 이벤트가 1건이라도 있으면 409 `'이벤트가 있는 캠페인은 삭제할 수 없습니다. 종료(보관)하세요'`. 집계 근거는 절대 지워지지 않으면서, 테스트·실수로 만든 빈 캠페인은 정리할 수 있다.
- **활성 폼 수 표시**(개정): 캠페인 목록(`/api/admin/analytics/campaigns`, `/api/admin/campaigns`)에 `forms`(전체)·`activeForms`(활성) 수를 넣는다. 진행중인데 활성 폼이 0개인 캠페인(예: 템플릿 삭제로 폼이 전부 꺼진 경우)은 대시보드에 "활성 폼 없음" 배지로 드러낸다. 상태를 자동으로 바꾸지는 않는다(운영자가 정한 상태를 시스템이 바꾸면 혼란).
- **종료**: `PATCH {status: 'archived'}` → 한 트랜잭션으로 캠페인 상태 변경 + 소속 폼 전부 `is_active=false`. 공개 페이지는 404, 배포 링크는 남는다(다시 켤 수 있도록), 집계·명단은 그대로 조회된다.
- **재개**: `PATCH {status: 'active'}` → 캠페인만 진행중으로. 폼은 자동으로 켜지지 않는다. 운영자가 폼별 활성 토글로 선택해 연다(종료 전 어떤 폼이 열려 있었는지를 기억하지 않는 대신 명시적으로 고르게 한다).
- 화면: 대시보드에 "종료 캠페인 숨기기" 토글(기본 표시). 캠페인 상세 헤더에 "삭제" 버튼(확인 대화상자, 이벤트 있으면 409 안내), "캠페인 종료" 버튼(확인 대화상자: 폼 N개가 닫히고 공개 링크가 404가 된다는 안내) / 종료 상태에서는 "다시 진행" 버튼. 대시보드 캠페인 표는 상태 배지로 구분하고 종료된 캠페인도 계속 보여 준다(성과 비교용).
- 종료된 캠페인에는 새 폼·링크를 만들 수 없다(409 `'종료된 캠페인입니다'`).

## 근거
- "종료"의 실질은 유입 차단이다. 상태만 바꾸고 폼이 열려 있으면 종료가 아니다.
- 삭제 대신 보관인 이유는 과거 성과가 다음 캠페인의 기준선이기 때문이다.
- 재개 시 폼을 자동으로 켜지 않는 것은 실수로 오래된 폼이 다시 열리는 것을 막기 위해서다.

## 대안
- 상태 3단계(초안/진행/종료): 초안은 "폼이 없는 진행중"과 구분이 안 된다. 필요해지면 추가.
- 종료 시 링크 삭제: 재개 시 SNS에 올린 링크가 죽는다. 링크는 남기고 폼만 닫는다.

## 결과
- 스펙 §4.3 PATCH 행에 부수 효과 명시, §5 캠페인 상세에 버튼 추가. e2e: 종료 → 폼 비활성·공개 404·stats 유지, 종료 캠페인에 폼 생성 409, 재개 시 폼은 그대로.
