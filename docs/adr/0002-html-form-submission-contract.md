# ADR 0002. 서버 주입 스크립트로 폼 제출을 가로채는 최소 계약

- 상태: 채택 (2026-09-09)

## 맥락
운영자는 AI로 만든 임의의 단일 HTML을 올린다. "범용 폼 빌더"는 범위 밖이므로 HTML 구조를 파싱해 필드를 정의하거나 편집기를 만들 수 없다. 그러나 신청 데이터는 우리 DB에 CRM 명단으로 저장돼야 한다.

## 결정
공개 폼 페이지를 만들 때 서버가 등록 HTML 끝(`</body>` 앞)에 작은 스크립트를 주입한다. 스크립트는 문서 안 모든 `<form>`의 submit을 가로채 `FormData`를 `{name: value}` JSON으로 바꾸고 `POST /api/public/forms/:slug/submissions`에 `visitToken`과 함께 보낸다. 성공하면 폼을 성공 메시지로 교체한다. 운영자 규칙은 "일반 `<form>`과 `name` 속성이 있는 입력"뿐이다.

## 근거
- 운영자가 HTML을 만들 때 우리 URL이나 특수 속성을 알 필요가 없다. 등록 전에 URL이 정해지지 않는 순환 문제가 사라진다.
- 필드 스키마를 강제하지 않으므로 어떤 폼이든 `payload JSONB`로 저장된다. CRM 명단은 payload를 그대로 보여 준다.
- 스크립트가 서버에서 주입되므로 제출 URL과 visit 토큰을 서버가 통제한다.

## 대안
- `data-lead-form` 같은 속성 규칙: 등록 시 검증은 되지만 AI 프롬프트에 규칙을 넣어야 하고, 규칙을 어긴 HTML을 거절해야 한다.
- 운영자가 `action`을 우리 URL로 직접 지정: 폼을 만들기 전에 slug를 알아야 하고, 네이티브 폼 제출은 sandbox iframe에서 페이지 이동을 일으킨다.

## 결과
- `<form>`이 하나도 없는 HTML은 등록 시 400으로 거절한다(최소한의 사전 검증).
- 파일 입력은 JSON으로 직렬화되지 않으므로 무시한다. 범위 밖으로 둔다.
- 등록 HTML 안에 자체 submit 핸들러가 있으면 우리 리스너와 함께 실행될 수 있다. 캡처 단계에서 리스너를 등록하고 `preventDefault`로 네이티브 이동을 막는다.
